# Historical PTC prompt comparison — 2026-09-15

**Scope:** these trials used the injected client in original PR #1516
(commit `c5c1210d2`), before SDK extraction. Both variants already supported
PTC. They do not compare PTC capability against the original tool set and do
not validate the current `@tools` SDK import. The current SDK-based prompt
requires a new evaluation after SDK publication.

## Decision in the original experiment

The original PR retained the compact PTC wording in `prompt/default_prompt.mbt.md`, with the Chinese
translation synchronized. It makes the lifetime and failure contract explicit:
complete calls and join spawned tasks before returning, inspect errors before
dependent work, re-read files after an uncertain mutation, and preserve URLs
and relevant failures when filtering output. Direct tools and `edits_file`
remain available. This does **not** change the default value of `ptc`.

The compact prompt improved the free-choice file-edit traces in this small
sample with unchanged correctness. Explicitly requested PTC remained correct
but needed more repairs. These results support the clearer contract and a
limited improvement on the free-choice fixtures, **not** a general speed or
reliability claim for PTC. The expanded first candidate was rejected because it
made the simple-edit control worse. No further candidates were tried.

## Method

48 live `deepseek-v4-flash` trials: two candidates, each compared against a fresh
baseline, with three repetitions per variant/case. Each candidate had a
free-choice cohort (single edit, computed edits, search; 18 trials) and a
separate cohort explicitly requesting PTC (computed edits; 6 trials). The two
cohorts answer different questions and should not be pooled into a performance
score.

The same prebuilt CLI, model, fixture bytes, 24-step cap, and 600-second timeout
were used for both variants. Variant launch order alternated across repeats;
concurrency was three for free-choice and two for required-PTC trials. Both
variants replaced only the PTC section of the same rendered base prompt, with
the references tree already expanded. No global skills were loaded. The
English prompt was evaluated; the Chinese translation was not separately
model-tested.

The machine-readable `results-2026-09-15.json` (all trial metrics, prompt
hashes, binary hashes, and artifact directories) is regenerated by the runner
and is not committed. Full prompts, original
logs, sessions, and workspaces remain in the ignored `.moonagent/eval_runs/`
directories named there. API keys are inherited and excluded from artifacts.

tool results, including compiler errors later repaired by the model.

| --- | --- | --- | --- | --- |
| Single edit, free choice | 3/3 → 3/3 | 16 → 14 | 1 → 1 | 399,957 → 351,895 |
| Computed edits, free choice | 3/3 → 3/3 | 27 → 21 | 7 → 3 | 911,985 → 566,992 |
| Search, free choice | 0/3 → 1/3 | 24 → 25 | 0 → 0 | 723,635 → 744,884 |
| Computed edits, PTC required | 3/3 → 3/3 | 30 → 33 | 6 → 8 | 865,576 → 984,768 |

The six free-choice file trials per variant used 43 → 35 steps, 8 → 4 errors,
and 1,311,942 → 918,887 reported tokens. The compact candidate used direct tools
in all of those runs, so these savings must **not** be attributed to PTC.

In the required-PTC cohort, every run used the bundled client successfully.
One candidate run initially submitted an empty edit batch; the host rejected it
without mutation and the model corrected the request. Another candidate run
needed repeated compiler repairs, explaining much of the regression. No PTC
request was left interrupted at exit. The sample is too small to establish a
stable performance difference.

The expanded prompt duplicated the tool API and included a full edit example.
Its simple-edit control added steps and compiler errors. The original wording
is preserved in `candidate_expanded.md`; it was not shipped. One search trial
successfully made eleven nested searches across three foreground scripts,
demonstrating that the live provider works through PTC, but this is not evidence
that searches should always use it.

## Interpretation and limits

- All **36 file-edit trials passed** their final byte/protected-file oracles.
  Computed-edit summaries also contained the correct count (12) and sum
  (24,290). Transcript inspection confirmed host editing tools were used and
  final file contents were re-read before completion.
- Only **3/12 search trials passed** the strict format/provenance oracle. The
  provider often returned translated documentation or official repository
  sources instead of the canonical page. Models sometimes substituted a
  familiar canonical URL or changed its fragment; one answer used a Markdown
  fence despite the JSON-only instruction. These are retained as failures.
  The strict host allowlist also rejects official repository documentation,
  so it is not a complete semantic correctness judgment. Passing URLs were
  checked for provenance, not exhaustively graded for relevance.
- Search scores were initially inspected using a loose substring oracle. The
  checked-in results were all reanalyzed with the final stricter oracle:
  exact URL membership in structured search results, without treating later
  script output as search evidence. Both variants use that same oracle.
- There were no process timeouts or interrupted nested requests. This live
  sample cannot prove freedom from deadlock; the deterministic bridge tests
  cover cancellation, joining handlers, shared-state serialization, and
  endpoint revocation.
- Three repetitions are exploratory. Shared provider caches, live search
  variability, trial labels in workspace paths, and concurrent machine load
  limit causal interpretation. Tokens include replayed/cached context and the
  agent's reported usage; they exclude separate search-provider usage. No
  dollar-cost estimate is made. Across all 48 trials, reported usage was
  11,197,243 tokens: 11,032,923 input (10,367,488 cached) and 164,320 output.

## Validation

All six offline oracle tests passed, including under `python3 -O`. They reject success claims without edits, protected-file
changes, missing computed summaries, unobserved search URLs, and ignoring an
explicit PTC request. They also check nested error/interruption accounting.
The original generated English prompt was compared byte-for-byte with the
compact candidate's saved full prompt. `just check`, `just test`, and `just build` passed after the prompt update:
3,138 native tests, 3,243 JS tests, 38 cram cases, CLI lifecycle checks, and
offline workflows. Final `moon info && moon fmt` introduced no interface or
formatting changes.
